# 08 できないことと分かっている問題

Agorack の限界、分かっている問題、決めていないこと、文書とコードの食い違い、確かめられなかったことを並べる。直す前に読むこと。

パスは abeouga/agorack のもの。出どころの無い項目は、2026-11-12 の main（`1c3a29b`）のコードから読んだものである。

---

## 1. 作らないと決めたこと

最初の版で作らないと決めたもの（`docs/architecture.md` §1、Epic #12「今回やらないこと」）。不具合ではない。

| 作らないもの | 今の動き |
| --- | --- |
| drive-logger（カブロガー）の接続と走行の表示 | 走行の根拠が来ても、ラベルと値だけで出す |
| 会話の保存（データベース） | サーバーのメモリとブラウザーの `localStorage` だけ |
| ログイン・利用者の区別 | 手元の PC だけで動かす。ループバックの住所でしか待ち受けない |
| 画像の受け取りと部品への取込の依頼 | 質問は文字だけ（4000 文字まで） |
| 文章のベクトル検索（RAG の索引） | 値は部品の道具で引く |
| 値の修正・確定 | 部品の画面で行う（約束3） |
| ログインがある部品の画面の埋め込み | ログインの状態の受け渡しは次の版で考える（決定 0004 の「影響」） |

## 2. 限界（今の作りから来るもの）

| 限界 | なぜそうなるか | 出どころ |
| --- | --- | --- |
| 「値を作らない」「計算は部品に任せる」は、Claude への指示で頼んでいるだけで、コードで守らせていない | 答えの文章は Claude が自由に書く。答えの値が道具の結果にあるかを照らす仕組みは無い | `agent/instructions.ts`、`agent/loop.ts` |
| 根拠は、部品が外枠を返さないと出ない | Agorack は外枠だけを見て取り出す。外枠の無い結果では、答えに根拠が付かず、右の欄も開かない。部品が外枠を返していないことを知らせる仕組みも無い | `evidence/extract.ts`、PR #26 の「見つけたこと」 |
| サーバーを起動し直すと、会話の続きが Claude に渡らない | サーバーの履歴はメモリだけ。ブラウザーには会話が残るので、画面は新しい会話をサーバーに作って同じ質問を送り直すが、前のターンは渡らない | `conversations/conversations.ts`、`apps/web/src/features/chat/useChat.ts` |
| 会話は消すまでサーバーのメモリに残る | 古い会話を片づける仕組みが無い | PR #25 の「未対応事項」 |
| 起動時につなげなかった部品は、サーバーを起動し直すまでつながらない | つなぎ直すのは「途中で切れた部品」だけ。部品をあとから起動しても、Agorack は気づかない | `sources/catalog.ts`、`catalog.test.ts` |
| 答えの表の行と根拠のつながりは、文字の一致で決める | 表は Claude が書いた Markdown で、どの根拠かは書かれていない。値を根拠と違う書き方で書かれると、行がつながらない。同じ値の根拠が2つ以上あってラベルでも決まらない行もつながらない（合計の行など） | `features/evidence/selection.ts`、[05](05-根拠と右の欄.md) §3.2 |
| 道具の結果は、全部をそのまま Claude に渡す | 大きい結果（`get_document` は根拠 111 件ぶん）も要約せずに渡す。要約だけを渡す案は次の版で考える | `agent/loop.ts`、`docs/architecture.md` §11 |
| 道具の入力が JSON として読めないと、ターンが失敗する | 読めなかった呼び出しを Claude に返して言い直させるには、ポートを広げる必要がある。起きたら別の Issue で扱う、としている | PR #22 の「未対応事項」 |
| 1回の応答で上限を超える数の道具を呼ぼうとすると、1つも呼ばずに終わる | 一部だけ呼ぶことはしない（[03](03-会話のループ.md) §3） | `agent/loop.ts` |
| 埋め込みの強調を外せない | 文之助の `agorack:highlight` は `fieldId: null`（強調を外す）も受け付けるが、Agorack の契約は空でない文字だけ。欄の ID の無い根拠では、前の強調が残る | PR #31 の「未対応事項」 |
| 埋め込みに一度失敗した記録では、試し直さない | 失敗は画面の中で覚え、部品を起動し直しても、同じ表示の中では埋め込みに戻らない | `renderers/index.tsx`、PR #31 |
| 道具を呼ぶ合間の短い説明は画面に出ない | `claude-opus-5-5` では考えた過程のブロックで返り、今の設定では中身が空になる。出したくなったら設定を足す | PR #22 の「未対応事項」 |
| 設定でモデルを替えたとき、そのモデルが `fallbacks` に対応していなければ、切り替えなしで動く | API の決まりで失敗はしない | PR #22 の「未対応事項」 |

## 3. 分かっている問題

| 問題 | 中身 | 出どころ | 状態 |
| --- | --- | --- | --- |
| つながらない部品の理由の文が長い | 理由に「部品の標準エラーの最後：…」と MCP の記録の行まで入り、それが Claude への指示と画面の知らせにそのまま出る | PR #29 の「未対応事項」 | 直していない |
| 文之助の `get_document` の要約が長い | 書類 ID と確定の日時まで入った1行になる。画面では1行に切り、全文は `title` に出す | PR #26 の「見つけたこと」 | 画面で切っている。短くするなら文之助の側 |
| `scripts/screenshots.ts` が、無くなったクラスを待って止まっていた | `.embed-fallback-notice` を待っていた | PR #41 | PR #40 で `.document-notice` に直した |
| 根拠の「同じ」の決め方が、サーバーと画面で違う | サーバーは部品・記録・`kind`・`location` で決め（`evidence/extract.ts`）、画面は部品・記録・`kind`・`label` で決める（`features/evidence/selection.ts` の `evidenceKey`）。ラベルが同じで場所が違う根拠は、画面では同じものとして扱われる | コード | 不具合として出た記録は無い（未確認） |

## 5. 文書とコードの食い違い

2026-11-12 に見比べて見つけたもの。どれも動きには影響しないが、読む人を迷わせる。

| 所 | 食い違い |
| --- | --- |
| `README.md`「状態」 | 「設計を終え、最初の版を作っているところです」のまま。最初の版の Epic #12 と、右の欄の Epic #37 は閉じている |
| `README.md` の偽のサーバーの表 | 「埋め込めない」（埋め込み用の画面が応えず、時間切れで戻る）の行が無い。`apps/web/dev/mock-api/scenarios.ts` にはある |
| drive-logger の id と名前 | 設定の見本は `cub`（`config/sources.example.json`）、偽のサーバーは `kabulogger`（`scenarios.ts`）。文書とコードでは「カブロガー」、部品のリポジトリの名前は drive-logger |
| 決定 0005 の決定 1 | 「外の枠の padding 12px」と書かれ、同じ文書の追記で 0 に直している。読むときは追記を正とする（`docs/architecture.md` §7.3 は 0） |

部品の解説は、もとは Agorack の `docs/parts/` にあり、2026-11-12 にこの解説のリポジトリの `fuminosuke/`・`drive-logger/` へ移した。文之助の解説から Agorack の決めごとへのリンクは、GitHub の URL に直してある。

## 6. 確かめられなかったこと（未確認）

| こと | なぜ確かめられなかったか |
| --- | --- |
| HTTP（Streamable HTTP）の部品への接続 | コード（`sources/mcp/client.ts`）はあるが、自動の試験は stdio だけで、HTTP の部品につないだ記録も Issue・PR に無い |
| ターンの途中（道具の呼び出しの最中）で部品が切れたときの、本物での動き | PR #29 では、止めたのはターンとターンの間。途中で切れる場合は `catalog.test.ts` の偽の接続で確かめただけ |
| 考えた過程のブロックが途中で別のモデルに切り替わったときの、本物での動き | PR #22 は偽の SSE の試験だけ。断られる質問を本物で試した記録は無い |
| 呼び出しの回数の上限（既定 20）に本物で達したときの答え | 偽のポートの試験だけ。通しの確認の問いは 1〜3 回の呼び出しで終わっている |
| 文之助以外の部品で、Agorack の中心を直さずに足せるか | 2つめの部品がまだ無い。偽のサーバーの「走行」の根拠で、知らない kind の表示を見ただけ |
| 文之助の実データ（`__fixtures__/fuminosuke/`）の書き出しの手順 | リポジトリに手順やスクリプトが無い |
| 人に使ってもらった記録 | Issue・PR に無い |
| 一部だけの道具を呼ばずに止める理由、起動時の失敗をつなぎ直さない理由 | コードと試験に決まりはあるが、理由を書いた記録が無い（[02](02-設計の考え方.md) §4） |
